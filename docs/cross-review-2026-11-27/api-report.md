## The scan design, read as one

The pairs the brief named:

| Pair of rules                                                          | Verdict                                   | Evidence                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ---------------------------------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| D70 bounds × D93 segments                                              | holds                                     | Each segment's view has `minLastL0Seq` as the largest `flushedSeq` so far and `maxLastL0Seq` as the snapshot. A flush past the snapshot leaves no manifest that fits, which becomes `SnapshotExpired`: a restart before any row, and `OvertakenByFlush` with `resumeFrom` = the segment's start after rows. The reader checks the manifest before it emits a row of the segment, so that `resumeFrom` is the first key not returned. |
| D93 restart × D108 budget                                              | holds                                     | A restart happens only with nothing emitted, and before the manifest check, so it spends no budget twice. A page restarted after earlier segments spent budget may end sooner; it still moves on.                                                                                                                                                                                                                                    |
| D108 budget × D125 settled keys × D93 segments                         | **broken**                                | Finding 1.                                                                                                                                                                                                                                                                                                                                                                                                                           |
| D125 settled keys × TTL                                                | holds                                     | `resolveVisibleRow` stops at the newest value or delete; an expired value hides the older ones. So dropping a settled key's older writer versions changes no answer, the transaction's retained rows included.                                                                                                                                                                                                                       |
| D76 manifest choice × the transaction page                             | holds                                     | Every segment and page uses `freshness: Recent`, the begin manifest as fallback, and bounds `[retainedFromSeq or flushedSeq, readSeq]`, as `getAt` does. A pinned page the writer has trimmed past `readSeq` cannot fit, which is `SnapshotExpired`, then `SnapshotTooOld`.                                                                                                                                                          |
| D119 snapshot check × the scan's `snapshotView`                        | holds                                     | A snapshot scan goes through `manifestFor`'s named branch, which compares `lastL0Seq` with the snapshot's sequence number.                                                                                                                                                                                                                                                                                                           |
| D125 shared budget × the routed page × D93's `OvertakenByFlush` resume | holds, but has finding 1's per-call guard | A shard's resume is a new `client.scan` with the page's remaining rows and the same budget.                                                                                                                                                                                                                                                                                                                                          |
| D57/D59 routing retry × D93 lazy pages                                 | **broken**                                | Finding 2.                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Handlers' lookahead row × an early end                                 | holds                                     | Both handlers ask for `limit + 1`, and an early end is accepted only with `rows.length <= limit`. A failure after the lookahead cannot happen, because the scan stops at `limit + 1`.                                                                                                                                                                                                                                                |
| D113 skip × D93 byte cut in `changelogRows`                            | holds                                     | `coveredUpTo` moves only after an entry is read whole. A cut ends the page before that, and rows above `upToSeq` are skipped whatever `coveredUpTo` says.                                                                                                                                                                                                                                                                            |
